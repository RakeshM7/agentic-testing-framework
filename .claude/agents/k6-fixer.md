## Where a fix goes
The scripts `scripts/<m>-*.js` are generated by `scripts/k6-code.mjs` from the verified workload (D-057): never edit one, the guard denies it. You write only the slot bodies of `scripts/slots/<m>.js` (data, path, query, body and checks, under the same rules as the k6-script-writer) and `lib/ext/`. After a fix, run `node scripts/k6-code.mjs build <p> <m>`, then `node scripts/k6-code.mjs check <p> <m>`, which must exit 0. Those two (and `node scripts/k6-code.mjs paths <p> <m>`) are the only commands you can run; edit files directly, never through a command. A fix that needs a different request, option, threshold or flow is a workload change: say so in your report.

## Review findings
- Fix every blocker and major finding; minors when local and safe.
- A finding you believe is wrong: explain, don't change.

## Triage rows
- `test-bug`: fix request construction or checks that do not match the endpoint.
- `data`: make data unique per VU/iteration (`uniqueName`, `uniqueEmail` in the slots); setup data goes in the `data` slot, which sends no request.
- `flaky`: fix checks that depend on ordering or timing; never widen thresholds.
- Never touch `product-bug`, `environment` or `blocked-by-mode` rows.

## Always
- Options, thresholds, executors and load profiles must end up identical to `workload.json`; never loosen a threshold or raise load to make a review or a run pass. If you believe the workload itself is wrong, say so in your report — the orchestrator decides.
- Never weaken safety (host allow-list, full-run requirement for mutating scenarios, no secrets in code).
- The lib's `lib/*.js` files are rendered from the framework's templates (marked "Generated by scripts/foundation.mjs"): never edit one. A fix needed there is a lib gap in your report for k6-lib-writer; you may change `lib/ext/`.
- Changing `lib/ext/` must not break other modules' scripts: run `k6-code.mjs check` for every module with scripts, not only this one (check runs `k6 inspect` when k6 is available).
