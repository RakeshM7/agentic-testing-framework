## Domain: Playwright UI
`<domain>` is `playwright-ui`.

### Inputs
The findings or triage file; `{fw}/docs/playwright-conventions.md`; the files it points to under `playwright-tests/<p>/{pages,fixtures/ui,helpers/ui,tests/ui}/`; for triage, `test-results/ui/` traces and error contexts; `artifacts/<p>/modules/<m>/explore/` (DOM snapshots for current labels) and `testcases/` when a fix needs ground truth.

### Owned files
Page objects (`pages/<m>/`), the regions of `tests/ui/<m>/cases.spec.ts`, the data builders (`helpers/ui/<m>.data.ts`) and `helpers/ui/<topic>.ts`. Nothing else:
- in `cases.spec.ts`, edit only inside the `// ui-code:begin` … `// ui-code:end` regions; steps go through page-object methods, never a raw locator or `test` call;
- never edit `tests/ui/<m>/_locators.smoke.spec.ts` or `fixtures/ui/pages/<m>.ts`, which the script generates, nor the files marked "Generated by {fw}/scripts/foundation.mjs" (`config/ui/`, `fixtures/ui/base.ts`, `fixtures/ui/auth.setup.ts`, `fixtures/ui/index.ts`): a fix needed there is a foundation gap, an `out-of-scope` entry;
- `node {fw}/scripts/ui-code.mjs paths <p> <m>` lists the scaffolded code.

### Domain specifics
- A page-object fix keeps the locator rules of `{fw}/docs/playwright-conventions.md`: names copied verbatim from the template's state snapshots, a CSS or XPath selector only with its cited reason.
- `test-bug`: fix the locator (verbatim from the snapshot or trace), the wait (web-first, never `waitForTimeout`), or the assertion only if it contradicts the test case.
- `flaky`: wait for the right state, isolate data. `data`: unique data (`uniqueName`) or preconditions created in the test.

### Verification
After every change run `node {fw}/scripts/ui-code.mjs build <p> <m>` (it re-renders the smoke from the page objects), then `node {fw}/scripts/ui-code.mjs check <p> <m>`, which also runs `tsc` and `playwright test --list`. Outside a scaffolded module, run `npx tsc --noEmit` and `npx playwright test --project=ui tests/ui/<m> --list`.
