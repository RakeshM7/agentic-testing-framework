## Domain: k6
`<domain>` is `k6`. You repair scripts, not results.

### Inputs
The findings or triage file; `{fw}/docs/k6-conventions.md`; `k6-tests/<p>/lib/`, `scripts/<m>-*.js` and the slot file `scripts/slots/<m>.js`; for triage, `results/*.summary.json`; `artifacts/<p>/modules/<m>/k6/workload.json` (ground truth for options and thresholds), `k6/code-plan.json` and `api/discovered-endpoints.json`.

### Owned files
The scripts `scripts/<m>-*.js` are generated by `{fw}/scripts/k6-code.mjs` from the verified workload (D-057): never edit one, the guard denies it. You write only the slot bodies of `scripts/slots/<m>.js` (data, path, query, body and checks, under the same rules as the k6-script-writer) and `lib/ext/`. Edit files directly, never through a command.
- The `lib/*.js` files are rendered from the framework's templates ("Generated by {fw}/scripts/foundation.mjs"): a fix needed there is a lib gap, an `out-of-scope` entry for k6-lib-writer.
- A fix that needs a different request, option, threshold, executor or flow is a workload change: a `needs-human` entry saying so; the orchestrator decides.

### Domain specifics
- Options, thresholds, executors and load profiles must end up identical to `workload.json`; never loosen a threshold or raise load to make a review or a run pass.
- `test-bug`: fix request construction or checks that do not match the endpoint.
- `data`: unique per VU and iteration (`uniqueName`, `uniqueEmail` in the slots); setup data goes in the `data` slot, which sends no request.
- `flaky`: fix checks that depend on ordering or timing; never widen thresholds.

### Verification
After a fix run `node {fw}/scripts/k6-code.mjs build <p> <m>`, then `node {fw}/scripts/k6-code.mjs check <p> <m>`, which must exit 0 (it runs `k6 inspect` when k6 is available). A change to `lib/ext/` must not break another module's scripts: find the other modules whose slot files import what you changed (search `scripts/slots/*.js` for the file name), and `node {fw}/scripts/k6-code.mjs check <p> <other-module>` must pass for each of them as well; you verify this module's scripts and those dependants, no others. A module that does not pass because of the change is reported in a `not-fixed` entry or a note, never repaired in its slot file. `node {fw}/scripts/k6-code.mjs paths <p> <m>` lists the files.
