# Playwright repo conventions (`playwright-tests/<product>/`)

One repo per product holds both UI and API tests. Every Playwright agent follows this file; reviewers check against it.

## Layout and ownership

```
package.json, package-lock.json, playwright.config.ts, tsconfig.json,
.env.example, .gitignore, README.md, utils/shared/          pw-repo-owner (only), rendered
config/ui/   fixtures/ui/   helpers/ui/   pages/<m>/   tests/ui/<m>/        UI agents
config/api/  fixtures/api/  helpers/api/  clients/<m>/ tests/api/<m>/       API agents
.auth/ (git-ignored storage state)   test-results/{ui,api}/ (git-ignored)
```

### The foundation is rendered from templates (D-054)

The fixed files are not written by hand: `node scripts/foundation.mjs render <p> --side repo|ui|api` renders them from the framework's [`templates/playwright/`](../templates/playwright/), which are the source of truth for their code. Each carries a "Generated by scripts/foundation.mjs — do not edit" header (the JSON files are listed in `.foundation-managed.json`), and `foundation.mjs check` and the gate fail on a hand edit.

| Side | Managed (rendered) | Extension (hand-written) | Judgment (cited overlay) |
|---|---|---|---|
| repo | the shared files above (`package.json`'s dependency versions and `package-lock.json` excepted from the drift check) | — | `repo-overlay.json`: dependency names, env names, ignores, whitelisted config values (pw-repo-owner) |
| ui | `config/ui/settings.ts`, `config/ui/README.md`, `fixtures/ui/base.ts` (the mutation guard), `fixtures/ui/auth.setup.ts` | `fixtures/ui/index.ts`, `helpers/ui/` | `ui-overlay.json`: loading indicator, cookie banner, timeouts, a recorded login form (pw-ui-scaffolder) |
| api | `config/api/settings.ts`, `config/api/README.md`, `fixtures/api/base.ts` (the guard, `noAuth`, `malformedAuth`, `identity`), `fixtures/api/auth.setup.ts`, `helpers/api/schema.ts` | `fixtures/api/index.ts`, `helpers/api/`, `config/api/schemas/` | `api-overlay.json`: base paths, auth scheme, default headers (pw-api-scaffolder) |

The overlays live in `artifacts/<p>/foundation/`. Dependencies are named without a version: `foundation.mjs install` resolves the latest at creation, and from then on `package-lock.json` pins them.

Within a side: the scaffolder writes the side's overlay and renders the foundation; later it fills only a reported gap, in `helpers/<side>/`. The pom- or client-writer adds one fixture per page object or client to `fixtures/<side>/index.ts`, which builds on `./base` (and the client-writer adds `config/api/schemas/`). The tests-writer writes the specs and the module's data or payload builders in `helpers/<side>/`. The fixer edits any of these except a managed file to apply findings.

A change to a file you don't own, or to a managed file, is a request in your report to your orchestrator — never an edit. The guard denies every agent a direct write to a managed file.

## Projects (`playwright.config.ts`)

`setup-ui` (testMatch `fixtures/ui/*.setup.ts`) → `ui` (testDir `tests/ui`, depends on `setup-ui`, storage state `.auth/ui.json`), `setup-api` (`fixtures/api/*.setup.ts`) → `api` (testDir `tests/api`). TypeScript, `fullyParallel: false` by default, retries `1`, trace `retain-on-failure`, reporter `list` (the runner adds `json`), output in `test-results/<side>/`. The only setup file of a side is the rendered `auth.setup.ts`; Playwright lists its setup test with the side, and the gate does not count it as a test.

## Environment (`utils/shared/env.ts`; values from `.env`, never hard-coded)

`BASE_URL`, `API_BASE_URL`, `STORAGE_STATE` (path to a human-produced storage state, optional), `ATF_MODE` (`readonly` | `full-run`, set by the runner from `state/run.json`), `ATF_PRODUCT`, `ATF_RUN_ID`, `ATF_REPO_ROOT` (framework repo root, for the ledger); `LOGIN_USERNAME` / `LOGIN_PASSWORD` (UI credential login) and `API_TOKEN`, `API_KEY`, `API_USERNAME`, `API_PASSWORD` (the API auth scheme's variable). Credentials only via the `.env` file the run-config's `credentials_file` points to. `.env.example` lists names with empty values.

## Login (`fixtures/<side>/auth.setup.ts`)

`STORAGE_STATE` always comes first. A UI credential login is rendered only when the UI overlay cites a plain login form the exploration recorded as a state; its selectors are that snapshot's own roles and names. CAPTCHA, MFA or a login on another host (single sign-on) is never automated: setup fails with an instruction to provide `STORAGE_STATE`. The API's `session` scheme reuses `STORAGE_STATE` or the UI's `.auth/ui.json`; header schemes read their variable per request.

## Safety in code

- A test that creates, changes or deletes data has `@mutates` in its title. The config sets `grepInvert: /@mutates/` unless `ATF_MODE === 'full-run'`.
- UI fixtures install a mutation guard (`fixtures/ui/base.ts`, an auto fixture): when `ATF_MODE !== 'full-run'`, requests to the product's hosts with a method other than GET/HEAD/OPTIONS are aborted. API fixtures (`fixtures/api/base.ts`) wrap every request context in `guarded()`, so non-GET calls throw `Mutation blocked: readonly run` outside full-run. `fixtures/<side>/index.ts` always builds on `./base`. Auth setup files are the only exemption (they must log in).
- Every entity a test creates is recorded immediately with `recordCreated({ type, ref, module, label })` from `utils/shared/ledger.ts` (it runs `node $ATF_REPO_ROOT/scripts/ledger.mjs add …`), deleted only after `owns(type, ref)` is true, and recorded with `recordDeleted`. Clean up in `afterEach`/`afterAll`.
- Test data is unique per run: `uniqueName(prefix)` from `utils/shared/data.ts` (includes `ATF_RUN_ID`).

## Code rules

- Test titles start with the test case id: `test('TC-contacts-3 creates a contact with required fields @mutates', …)`. One `describe` per test case group; tags in titles mirror the test case tags (`@p1`, `@negative`, …).
- Locators: `getByRole` / `getByLabel` / `getByPlaceholder` / `getByTestId` first; text copied verbatim from `explore/pages/<slug>/dom-snapshot.md`; CSS/XPath only when nothing else exists, with a comment why.
- No `waitForTimeout`, no fixed sleeps; web-first assertions (`await expect(locator).toBeVisible()`).
- Page objects (`pages/<m>/<page>.page.ts`): class per page, constructor `(page: Page)`, locators as readonly properties, actions as async methods, **no assertions**.
- API clients (`clients/<m>/<resource>.client.ts`): class per resource wrapping `APIRequestContext`, typed request/response, **no assertions**.
- Helpers (`helpers/<side>/`): pure functions (builders, formatters, parsers); no Playwright fixtures inside.
- Fixtures (`fixtures/<side>/index.ts`): `import { test as base } from './base'`, then `export const test = base.extend<…>()` providing the page objects or clients; `export { expect } from './base'`. The guard (the UI mutation guard, the API's guarded contexts) lives in the rendered `fixtures/<side>/base.ts` and the login in `auth.setup.ts`, never in `index.ts`; `index.ts` never takes `test` or `expect` from `@playwright/test` (type-only imports are fine).
- Visual checks (`@visual` cases): `toHaveScreenshot()` with masks for dynamic regions; baselines are created by the runner with `--update-snapshots` only when none exist.
- `npx tsc --noEmit` must pass before handing back.

**Machine-checked** by `scripts/gate.mjs` before every review (findings in `gate-findings.md`): typecheck and `--list`; one test (or `test.fixme`) per test case (ui, all but `@api`) or plan scenario (api), and no test without one; `@mutates` in the title of every test whose case or scenario mutates; `@identity-<name>` in the title of every API test whose scenario needs that identity; `recordCreated` in specs with `@mutates` tests; no `waitForTimeout`; no hard-coded URLs or `test.only`; no assertions in page objects or clients; once the foundation is rendered, no managed file drifted from its render, `fixtures/<side>/index.ts` builds on `./base`, and no setup file but `auth.setup.ts`. `node scripts/foundation.mjs check` enforces the rest of the foundation's rules. Its URL check flags a full URL, a protocol-relative `'//host'`, and a URL assembled from pieces (a scheme joined with `+`, through `${'…'}`, or an array holding a scheme piece that is joined); a bare host literal such as `'acme.example.com'` is out of its scope and left to the reviewer. Everything else in this file is the reviewer's to judge.

## Running (runner-triagers only)

```
ATF_MODE=<run mode> ATF_PRODUCT=<p> ATF_RUN_ID=<run> ATF_REPO_ROOT=<repo> \
PLAYWRIGHT_JSON_OUTPUT_NAME=test-results/<side>/<m>-report.json \
npx playwright test --project=<side> tests/<side>/<m> --reporter=list,json
node $ATF_REPO_ROOT/scripts/results.mjs playwright <p> <m> <side> playwright-tests/<p>/test-results/<side>/<m>-report.json
```
