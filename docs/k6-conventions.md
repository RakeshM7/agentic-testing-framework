# k6 conventions (`k6-tests/<product>/`)

## Layout and ownership

```
lib/          k6-lib-writer      config.js, auth.js, checks.js, data.js, summary.js, settings.js (rendered)
lib/ext/      k6-lib-writer      hand-written additions for missing exports
scripts/      k6-script-writer   <m>-<scenario>.js, one workload entry (K6-<m>-<n>) per file
results/      k6-runner-triager  <script>.summary.json, <script>.created.json (git-ignored)
README.md     k6-lib-writer      how to run, env vars (rendered)
```

The lib, the README and `.gitignore` are rendered by `node scripts/foundation.mjs render <p> --side k6` from the framework's [`templates/k6/`](../templates/k6/), which are the source of truth for their code (D-054). Each carries a "Generated by scripts/foundation.mjs — do not edit" header; the guard denies a direct write, and `foundation.mjs check` and the gate fail on a hand edit. k6-lib-writer's judgment (the auth scheme, base path, default headers, missing-export requests) lives in its cited overlay `artifacts/<p>/foundation/k6-overlay.json`, and its own code in `lib/ext/`. `foundation.mjs check --side k6` runs `k6 inspect` on a temporary script of its own that imports every lib file.

## Safety in code

- `lib/config.js` reads `BASE_URL` and `K6_ALLOWED_HOSTS` (comma-separated) from `__ENV` and **aborts in `setup()`** unless `BASE_URL`'s host is in the list. There is no default `BASE_URL`.
- A script whose workload entry has `mutates: true` aborts unless `__ENV.ATF_MODE === 'full-run'`. k6 cannot call the ledger, so a mutating scenario deletes everything it creates within the same iteration, and passes anything it could not delete to `trackLeftover(type, ref)` from `lib/data.js`, which `handleSummary` writes to `results/<script>.created.json` (`[{type, ref}]`; k6 shares no state between VUs and `handleSummary`, so each leftover travels as a check name); the runner-triager records those in the ledger (`ledger.mjs add`) so they appear on the run's cleanup list.
- Live runs happen only in full-run runs (the guard enforces `load: run`); in readonly runs scripts are validated with `k6 inspect` only and results are recorded as `not-run`.

## Code rules

- Every script: `export const options = { scenarios, thresholds }` taken exactly from `workload.json`; `export { handleSummary } from '../lib/summary.js'`.
- `lib/summary.js` `handleSummary(data)` writes `results/<script>.summary.json` (the raw `data` object), `results/<script>.created.json` and a short text summary to stdout; the script name is `K6_SCRIPT` (else the options tag `script`).
- Checks via `lib/checks.js` helpers (status, JSON shape, latency); no `sleep()` without a think-time reason in a comment.
- Auth via `lib/auth.js` using env values only (`K6_USER`, `K6_PASSWORD`, or `K6_TOKEN`); never literals. There is no token exchange (no login request under load): `bearer`, `oauth2` and `api-key` send `K6_TOKEN`, `basic` sends `K6_USER` and `K6_PASSWORD`, `session` sends `K6_TOKEN` as the cookie the k6 overlay names (D-054).
- `k6 inspect scripts/<file>.js` must succeed before handing back.

**Machine-checked** by `scripts/gate.mjs` before every review (findings in `gate-findings.md`): `k6 inspect` on every script, one script per workload scenario (by its `K6-<m>-<n>` id), `assertAllowedHost()` and `requireFullRun()` called, `handleSummary` exported, `lib/config.js` present, no hard-coded URLs, and (once rendered) no lib file drifted from its render. Options and thresholds matching `workload.json`, and everything else here, is the reviewer's to judge.

## Running (k6-runner-triager only)

```
ATF_MODE=full-run BASE_URL=<target> K6_ALLOWED_HOSTS=<target host> K6_SCRIPT=<m>-<scenario> k6 run scripts/<m>-<scenario>.js
node <repo>/scripts/results.mjs k6 <p> <m> k6-tests/<p>/results/<m>-*.summary.json
```
Readonly run: `node <repo>/scripts/results.mjs not-run <p> <m> k6 --reason "readonly run: load tests only run in full-run"`.
